## Decisions made

- Kept the Hugoplate theme as a local copy in `themes/hugoplate/` rather than
  using Hugo modules to import it. This gives full control over layouts and CSS.
- Kept Hugo module imports in `config/_default/module.toml` even for modules
  we might not need yet (accordion, search, images, etc.). Easier to strip later
  than to debug missing partials.
- Removed Prettier from devDependencies since the project uses git-hooks for formatting.

## Colour audit and decision to drop Hugoplate

Audited the site colours by comparing screenshots of the live site against
the brand board (`anomalica/brand/brand-board.html`). Key findings:

1. Body text too light - using Slate (#5E5A50), brand board uses Graphite (#3D3B35)
2. Header has no visual presence - same colour as page body, brand board
   uses dark teal-950 with backdrop blur
3. No meaningful contrast between page sections - Paper and Bone are too
   close in value. Brand board alternates white, paper, and dark teal sections
4. Missing intermediate neutrals (Pebble, Graphite, Charcoal) that the
   brand board uses for visual hierarchy
5. Hugoplate's theme.json maps to ~8 colour slots; the brand board uses ~15
   distinct colours. The abstraction layer is too coarse.
6. Card borders, link underlines, nav active states, section labels - all
   styled differently in the brand board than what the template supports

Decision: drop Hugoplate entirely. The template's layout system, CSS
abstraction, and Hugo module dependencies are all fighting the brand
identity rather than supporting it. Building from first principles with
Hugo + Tailwind CSS v4 will be faster than continuing to override the
template at every turn. The brand board already serves as a complete
design system with working CSS patterns.
