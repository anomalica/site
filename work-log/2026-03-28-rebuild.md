# 2026-03-28: Rebuild from first principles

## Decision

Dropped the Hugoplate template after a colour audit showed the template's
abstraction layer was too coarse for the brand palette. The brand board uses
~15 distinct colours with specific semantic roles; Hugoplate maps everything
to 8 abstract slots. Every design decision required fighting the template.

## What was done

1. Removed the entire Hugoplate theme directory, config, scripts, and modules
2. Set up clean Hugo + Tailwind CSS v4 (via CLI, no wrapper scripts)
3. Added Alpine.js via CDN for interactivity
4. Built all layouts from scratch using the brand board's CSS patterns:
   - `baseof.html` - base template with dark mode init and font loading
   - `partials/header.html` - dark teal-950 nav with backdrop blur,
     language selector (28 languages), units selector, dark mode toggle,
     mobile hamburger with Alpine.js dropdowns
   - `partials/footer.html` - matching dark teal footer with subtle
     logo, About link, GitHub icon, and CC0/MIT licence text
   - `index.html` - homepage with teal-900 hero, white browse section,
     paper principles section, white status section
   - `_default/list.html` - section listing with cards
   - `_default/single.html` - article page with section label, teal
     pill tags, content links with brand-board underline treatment,
     references with teal left border
5. Wrote main.css with the full brand palette as CSS custom properties
   and component classes (section-label, tag, btn, content links)

## Results

- Build time: ~18ms (was ~1000ms with Hugoplate)
- 68 files changed, 1757 additions, 2967 deletions (net reduction)
- No Hugo module dependencies
- Dark header/footer bookend the page like the brand board
- Section labels are small uppercase tracked text (not large headings)
- Content links use teal-700 with teal-300 underline decoration
- Tags use teal pill styling

## Issues encountered

- Hugo escapes `<` in Alpine.js expressions in HTML attributes.
  The x-init on the `<html>` tag got mangled because Hugo's template
  engine treated `<` as HTML. Fixed by moving dark mode init to an
  inline `<script>` tag (runs before render to prevent flash) and
  putting Alpine's x-data/x-effect on `<body>` instead.

## Dark mode: still broken

Multiple attempts at dark mode have failed:

1. First attempt: teal-on-teal. Every dark surface was a shade of teal
   (teal-950, teal-900). Result was monochromatic, no contrast, no
   visual hierarchy. Headings and body text were indistinguishable.

2. Second attempt: warm neutral dark backgrounds (#141413, #1C1B19,
   #242320) with teal only for header/footer/accents. This created a
   split personality - warm grey content sandwiched between teal
   chrome. The two colour families clashed.

3. Current state: dark mode is nearly identical to light mode because
   the hero, header, and footer are already dark teal in both modes.
   The content area barely changes. Card titles became unreadable
   (dark text on dark background). Effectively there is no dark mode.

The fundamental problem is that the light mode design uses dark teal
for so much of the page (hero, header, footer) that there is very
little left for dark mode to actually change. A proper dark mode
needs to rethink the entire page, not just swap content surfaces.

This needs to be approached fresh in a new session.
